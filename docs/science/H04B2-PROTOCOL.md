# H04b.2 — контекстное смешивание и длинные совпадения
Протокол до вычисления метрик. 
## Задача
Проверить, насколько уменьшается prequential log loss при добавлении более длинного контекста и предиктора совпадений. Контекстное смешивание и match models известны (Mahoney, Adaptive Weighing of Context Models for Lossless Data Compression, 2005, https://repository.fit.edu/ces_faculty/166/; https://www.mattmahoney.net/dc/dce.html). Не CTW, не PAQ, не заявка на новизну.
## Данные
Silesia: первые 65536 B каждого из 12 файлов; проверка SHA-256 целого файла по лабораторному манифесту. Окна отличаются от центральных H04, но семейства повторно используются. Две новые локальные панели: text/code — /usr/lib/python3.12/argparse.py, ast.py, email/message.py, /usr/share/common-licenses/GPL-3; binary — /usr/bin/grep, sed, tar, find. Первые min(65536,n) B, SHA-256 целого файла и окна. Не запускать исследуемые файлы. Публичные/локальные панели не слепой holdout. Один прогон, модели сбрасываются на каждом образце; обучение только на уже наблюдённом префиксе. 
## Модели
A — H04 mixture (порядки 0,1,2,4, 65536 ячеек на порядок, исходные хеш/KT/фиксированная доля). B — порядки 0,1,2,4,8, таблицы 2^18 ячеек, последние k байтов и префикс текущего байта; 64-bit hash mix (xor shifts 30,27,31, multiply 0xbf58476d1ce4e5b9, 0x94d049bb133111eb), index low 18 bits; KT, saturation 4096 как H04. C — B + match model: хеш последних 4 байтов, таблица 2^18 последних позиций (проверка фактических четырёх байтов); продолжение совпадения при точном предсказании целого байта, иначе новый поиск; если прогнозируемый префикс совпадает, вероятность предсказанного бита 31/32, иначе 1/2. Только уже наблюдённые байты. D — C с раздельными весами для каждой из 8 позиций бита. B,C используют общие веса. Инициализация равными floor(65536/m), fixed share 64 + floor((65536-64*m)*w_i*l_i/sum(w_j*l_j)), Q=32768, quantization same as H04. Код модели и точные операции опубликованы.
## Метрики и gate
Сумма -log2(p observed) после целочисленной квантизации. Диагностический размер = ceil(loss/8)+15 (13B условный заголовок + 2B запас завершения; не измеренный архив и не доказанная граница). A–D: loss bits, CPU, match coverage. Контроли реальные потоки XZ5, 7z PPMd5, Zstd15, каждый восстановить; 7z включает имя, другие не включают; ZPAQ method 5 если доступен локально, отдельно, не обязательный gate. Сравнение прогнозной стоимости с реальными байтами только предварительный фильтр; не объявлять победу компрессора. 
H04b.2a: D уменьшает суммарный loss против A >=10% на каждой из трёх панелей. H04b.2b: D diagnostic size <=95% per-sample min(XZ5,PPMd5,Zstd15) на каждой панели. Только если оба проходят, реализовать реальное кодирование и новый заранее зарегистрированный независимый тест. Отдельно измерить B/A, C/B, D/C. Не менять пороги; пропуск образца делает gate непроверенным. CPU и память не являются критериями; нет доказательства скорости, peak RSS не измерен.
