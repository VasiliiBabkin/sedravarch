# SedravArch: исследование эффективного сжатия без потерь

**Статус:** рабочая научно-техническая рукопись, не рецензированная публикация. Начало: 24 ноября 2026 г.

## Аннотация
Цель — найти воспроизводимое преимущество перед сильными компрессорами при явно заданных ограничениях. Архитектура не фиксируется заранее. Устаревшие и неэффективные реализации не являются обязательствами проекта. Отрицательные результаты сохраняются как знания, а не как требования сохранять код.

## 1. Постановка задачи
Для источника X рассматриваем семейство обратимых представлений T_m и кодеров E_k. Требование D_k(E_k(T_m(X))) с последующим обратным T_m должно побайтно восстанавливать X. Минимизируем фактическую длину L = L(идентификатор модели) + L(параметры) + L(поток) + L(контейнер) при ограничениях CPU, памяти, времени декодирования и чтения при выборочном извлечении. Для разных рабочих нагрузок оцениваем фронт Парето, а не произвольную сумму несопоставимых единиц. По принципу Дирихле не существует инъективного кодирования, укорачивающего каждую n-битную строку.

## 2. Научный подход
- Информация и вероятность: условная энтропия, логарифмические потери, стоимость модели. Энтропия выборки не является нижней границей размера конкретного файла.
- Статистика: раздельные development/tuning/holdout по семействам данных, заранее фиксируемые критерии, парные сравнения, неопределённость, отрицательные результаты. Canterbury/Silesia — открытые регрессионные панели, не слепой holdout.
- Кибернетика: обратная связь от измеренной эффективности; адаптивное распределение вычислений только после проверки предсказателя. Не предполагаем, что усложнение повышает эффективность.
- Прикладная математика: дискретная оптимизация, графы зависимостей, комбинаторное кодирование; учитываем стоимость описания и ресурсов.
- Каждый эксперимент фиксирует конечное пространство кандидатов, seed, версии, идентичные данные, полный размер, корректность и ограничения. Не выдаём условный оптимум за глобальный теоретический предел.

## 4. Конкурирующие гипотезы
H01 — бюджет потенциальной экономии от автоматического выбора обратимых структурных преобразований. Сначала диагностический oracle, только затем механизм отбора.
H02 — грамматические и словарные представления с оптимизацией полной длины кода.
H03 — условное представление связанных файлов при ограничении стоимости доступа.
H04 — адаптивное контекстное моделирование и стоимость переключения моделей.
H05 — обратная связь и распределение вычислительного бюджета по измеренной полезности.
Ни одна гипотеза не является заранее выбранной архитектурой. H02–H05 требуют отдельных протоколов.

## 7. Условия отбора
На независимом наборе будущий алгоритм должен продемонстрировать практически значимое преимущество (например, ≥10% меньше при сопоставимых ресурсах либо ≥2× быстрее при сопоставимом размере). Это исследовательские цели, а не достигнутые результаты. Конкретные пороги каждого опыта фиксируются отдельно. Любая ошибка восстановления — основание остановить соответствующий вариант. Стабильный формат не является ограничением для прототипов.
