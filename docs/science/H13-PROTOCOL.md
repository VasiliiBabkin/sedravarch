# H13 — эмпирическая граница Парето для архиваторов
Протокол до измерений. Это screening существующих кодеров, не новый алгоритм. 
## Корпус
6 окон Silesia (dickens, mozilla, mr, osdb, samba, x-ray), по 1048576 B начиная с offset=floor((source_size-1048576)/3), SHA-256 полного файла по manifest. Новые локальные публичные данные: первые 1048576 B libsqlite3.so.0 и libcrypto.so.3 из /usr/lib/x86_64-linux-gnu; первые 1048576 B распакованных /usr/share/doc/libglib2.0-0t64/NEWS.gz и /usr/share/man/man1/ffmpeg-all.1.gz (сверка gzip CRC, исходные и канонические SHA-256). Группы Silesia и local отдельно, пофайловый анализ; новые локальные файлы ранее не тестировались в H01–H12, не независимый слепой holdout. Исследуются байты, не выполняются исполняемые файлы. Пропуск/ошибка явно фиксируются.
## Профили (все один CPU)
LZ4 -1/-9; gzip -6 -n; Zstd -1/-3/-9/-19 -T1; XZ -1/-5/-9 -T1 CRC64; Brotli -9; 7z LZMA2 -mx=5 -mmt=1 timestamps off; 7z PPMd -mx=5 -mmt=1 timestamps off; SedravArch v0.7 balanced 1 thread (ранее собранный контроль db9ccb936c713fe9c43a7308445889ae53a02029, не современная dev-ветка). 14 профилей. Полные форматы; input.bin для 7z и SDA, названия метаданных неодинаковы. 
## Измерения
3 повтора каждой пары, детерминированная перестановка профилей в каждом повторе (seed source hash + rep), новый процесс и файлы на каждый encode/decode, последовательное выполнение. Тёплый OS cache, no drop_caches. GNU time %U %S %M, wall через perf_counter_ns вокруг запуска, без внешней сверки; wall включает I/O и startup. Peak RSS KiB отдельно encode/decode, агрегаты max per-file medians, CPU diagnostic с гранулярностью 0.01 s. Файлы сравнивать побайтово, сохранять хеш потока и размер, отклонение размера/хеша между повторами отмечать. Сумма размеров и медиан wall по каждой группе; суммарные скорости input_bytes/sum wall. Учитывать только полностью проверенные профили для конкретной панели; не выдавать пропуски за преимущество.
Ограничения: один CPU affinity, nice+10, flock benchmark.lock, disk free >=5 GiB, MemAvailable >=1 GiB, RLIMIT_AS 2 GiB, file limit 64 MiB, timeout 30s на процесс, max job 300s, только лабораторная директория, tmp cleanup. 
## Парето и диагностические срезы
Вектор минимизации (bytes, encode wall, decode wall, encode peak RSS, decode peak RSS). Точное доминирование: <= по всем пяти и < хотя бы по одному. На группах и пофайлово; малые отличия времени не считать статистически значимыми. Дополнительно заранее фиксируем бюджеты: (A) encode >=20 MiB/s, decode >=50 MiB/s, encode/decode peak <=64 MiB; (B) encode >=5 MiB/s, decode >=20 MiB/s, encode/decode peak <=256 MiB; (C) decode >=10 MiB/s, decode peak <=16 MiB, encode peak <=512 MiB, без encode speed. Для каждого бюджета лучший фактический размер среди полных профилей; сравнение с unconstrained min. Если нет подходящего профиля, записать infeasible. Потенциальные разрывы — ориентир для новых гипотез, не доказательство фундаментальной слабости. Отдельный кандидат будущего эксперимента должен показать >=5% size savings относительно лучшего контроля в том же бюджете, либо >=2x throughput при <=101% размера и не худших прочих ресурсных ограничениях; на новом независимом корпусе. Никакого ретроспективного изменения критериев. В H13 только карта контролей, не gate нового кодера.
