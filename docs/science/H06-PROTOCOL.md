# H06 — числовые потоки: предсказание и адаптивное представление
Протокол второго цикла, до запуска.

## Научная база
Обратимые разностные и XOR-преобразования, байтовые/битовые перестановки известны. См. Masui, Bitshuffle (https://github.com/kiyo-masui/bitshuffle), Pelkonen et al., Gorilla (https://www.vldb.org/2015/program/lib/FullProgram.html), оценка научных компрессоров https://gmd.copernicus.org/articles/12/4099/2019/. Цель — оценка конкретных гипотез, не заявка на изобретение этих методов.

## Новые данные (не использовались в H01–H05)
- ECG: https://raw.githubusercontent.com/scipy/dataset-ecg/main/ecg.dat, np.load(allow_pickle=False), ключ ecg; 4 последовательных непересекающихся окна по 16384 значений из начала, канонический signed int16 LE (проверка целочисленности и диапазона). Если формат не соответствует, пропуск семейства.
- ETTh1: https://raw.githubusercontent.com/zhouhaoyi/ETDataset/main/ETT-small/ETTh1.csv, первые 16384 строки, 7 числовых колонок HUFL,HULL,MUFL,MULL,LUFL,LULL,OT, по отдельности, float64 LE. Дата не кодируется.
- M4: https://raw.githubusercontent.com/Mcompetitions/M4-methods/master/Dataset/Train/Hourly-train.csv, первые 12 строк с >=512 последовательными непустыми конечными числовыми значениями после идентификатора, первые 512 значений, float64 LE. Правило отбора по длине, не по сжимаемости.
- Synthetic: seed 20261125, 16384 int16 random, линейный int32 с малым шумом, кусочно неоднородный int32, float64 плавный синус и decimal-grid. Только диагностика.

Получение через HTTPS с лимитом 12 MiB на источник; SHA-256 скачанных исходников, ID/колонки и хеши канонических массивов сохраняются. Реальные источники различны, внутри семейства образцы зависимы; это новая публичная screening-панель, не слепой holdout. Сравниваем точное восстановление канонических бинарных массивов, НЕ исходных CSV/NPZ. Пропуск любой реальной панели делает общий gate непроверенным.

## Метод
Слово w=16,32,64 бит; работать с его битовым представлением как unsigned integer, без округления исходника. Фиксированные предикторы: id, XOR с предыдущим словом, delta1 (mod 2^w), delta2 (mod 2^w, x[i]-2*x[i-1]+x[i-2]); для delta применять обратимое ZigZag к знаковому интерпретированию остатка. Начальные предыдущие слова равны нулю. Для каждого предиктора три перестановки: identity, byte shuffle, bit shuffle (транспонирование всей матрицы битов с packbits). Два backend: XZ5 CRC64 и zstd15 single-thread (libzstd), плюс raw. Это сильное диагностическое меню известных операций, не официальная оптимизированная реализация Bitshuffle/Gorilla/ALP/FLAC.

H06a: oracle фиксированного меню, включая все 24 комбинации и raw, экономит >=10% относительно суммы per-sample минимумов прямого XZ5/Z15/raw на КАЖДОЙ реальной панели. Это потолок выбранного меню, не реализованный селектор.
H06b: блоковый адаптивный предиктор (256 слов), выбирать из 4 указанных предикторов минимальную сумму бинарных энтропий битовых полос блока; при равенстве меньший id; сохранять один tag на блок. Остатки вычисляются с учётом предыдущих слов глобально; объединить остатки и применить глобальное bit shuffle. Сжать tags+остатки zstd15 (основной) либо XZ5 (диагностика). H06b: основной adaptive-zstd не менее 5% экономии относительно oracle фиксированного меню на каждой из трёх реальных панелей. Суррогат суммы маргинальных энтропий не учитывает корреляции полос и словарь backend. Это проверяемая гипотеза, не оптимум.
H06c: для float64 проверить точное восстановление через целые y=round(x*10^k) в диапазоне |y|<=2^53-1, k=0..6; принять первый k, для которого (float64(y)/10^k).tobytes()==x.tobytes(). Не терять -0, NaN payload или другие биты; если нет подходящего k, вариант неприменим. Преобразовать y к int64 LE, delta1+zigzag+bitshuffle и сжать каждым backend; k хранить в заголовке. Диагностическая гипотеза, без общего gate; >=10% экономии против фиксированного oracle на конкретном массиве мотивирует дальнейший эксперимент против специализированного ALP/других float-кодеров. Не утверждать преимущество над ними.

## Учёт и критерии
Рамка 17 B: magic H06A, dtype width, backend id, predictor id, shuffle id, decimal scale (255 нет), u32 число слов, CRC32. Для adaptive внутри сжатого потока один tag на 256 слов; raw включает ту же рамку. Все байты рамки и тегов учитываются. Декодировать каждый реально сформированный поток; ошибка останавливает. Один прогон, CPU encode/decode, SHA-256, полный размер и tags histogram, статистики по семейству. Время Python не сравнивать как нативную скорость; RSS не измеряется. Не интегрировать даже при успехе без независимого holdout и специализированных контролей. Ни один результат не доказывает универсальность.
