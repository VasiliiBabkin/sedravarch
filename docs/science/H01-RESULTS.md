## Измерения
VDS, Linux, 2 доступных CPU, affinity одного ядра, nice +10, Python lzma FORMAT_XZ preset 5, CRC64, liblzma 5.4.5. Версии Python/NumPy, параметры и хеши окон зафиксированы в JSONL. Один прогон: времена диагностические, не статистически подтверждённые характеристики производительности.

## Решение и ограничения
Не реализовывать универсальный селектор из этих 14 вариантов: математический минимум в конечном меню недостаточен на обеих публичных панелях. Не переносить полученные результаты на все обратимые преобразования, другие кодеры и полные архивы. Преобразования могут быть полезны в узкой области, но сначала требуется отдельная заранее зарегистрированная проверка на новых числовых данных с сопоставимыми форматами и сильными специализированными контролями. В H01 не исследованы BCJ, разбор форматов, повторное сжатие DEFLATE, грамматики, контекстные модели и глобальные зависимости. Silesia представлена тремя окнами каждого файла, а не полными файлами. Измеряются XZ-потоки с байтом селектора, не полноценные именованные архивы. Отсутствует отдельный замер стоимости быстрого выбора модели; нет необходимости разрабатывать его до подтверждения локальной гипотезы.

## Воспроизведение
При наличии лабораторного корпуса с manifest.json и зависимостями Python + NumPy:
```bash
source ~/sedravarch-lab/bin/env.sh
cd ~/sedravarch-lab
python experiments/h01/h01_transform_oracle.py --lab "$SEDRAVARCH_LAB" --out results/h01-reproduction.jsonl
```
Выходной путь должен быть новым. Контрольные суммы входных окон в опубликованном JSONL. Временные файлы кодирования не создаются.
