# H03 — условное представление версий, ограничение глубины
Дата: 2026-11-24. Протокол до запуска.

## Гипотеза
H03a: при архивировании нескольких версий файла граф межфайловых дельт с ограниченной глубиной обеспечивает не менее 10% экономии полного размера против 7-Zip LZMA2 solid preset 5 на сумме выбранных реальных семейств и выигрывает хотя бы на двух из четырёх семейств. Это screening, не доказательство новизны или универсальности. Основы: [Principles of Dataset Versioning](https://www.vldb.org/pvldb/vol8/p1346-bhattacherjee.pdf), [RFC 3284](https://www.rfc-editor.org/rfc/rfc3284.html), [From Relative Compression to Hierarchical Compression](https://doi.org/10.4230/LIPIcs.SEA.2026.7). Дельта-кодирование и графы версий известны.

## Данные
Синтетическое семейство versions/v1.bin,v2.bin,v3.bin из лаборатории — development. Четыре публичных реальных семейства из тегов upstream (по три версии одного файла):
- zstd: facebook/zstd, v1.5.5/v1.5.6/v1.5.7, lib/compress/zstd_compress.c.
- libpng: pnggroup/libpng, v1.6.43/v1.6.44/v1.6.45, pngread.c.
- curl: curl/curl, curl-8_10_1/curl-8_11_1/curl-8_12_1, lib/http.c.
- Git: git/git, v2.45.0/v2.46.0/v2.47.0, diff.c.
Скачивание HTTPS raw.githubusercontent.com, лимит 2 MiB на файл; сохраняем URL и SHA-256. Если недоступны, фиксируем пропуск и не утверждаем прохождение gate. Не заменяем после измерений. Однородные исходники, не независимый blind holdout. Каждая версия именуется v1.bin/v2.bin/v3.bin одинаково для всех кодеров. Точные совпадения версий допускаются и отмечаются.

## Представление
Внутри каждого семейства для каждого i независимый XZ preset 5 CRC64 и дельта к каждому j<i, сжатая тем же XZ. Дельта — COPY(u32 offset,u32 length) и ADD(u32 length,bytes) с однобайтовым opcode, поиск 16-байтовых совпадений в базе с шагом 4 и до 8 первых позиций на ключ; жадное максимальное продолжение совпадения; без поиска самоссылок. COPY/ADD сериализуются полностью. Никакого выбора по тестовому holdout.
Контейнер: magic 8B, u32 count, для каждого файла u16 длина имени, UTF-8 имя, i32 parent (-1 независимо), u32 decoded length, u32 compressed length, u32 CRC32 исходника; затем последовательные payload. Позиции выводятся из длин, парсер может читать только таблицу и нужные payload. Имена, целостность включены, timestamps отключены также для 7z. Нет претензии на одинаковую структурную стоимость разных контейнеров.
Перебираем все графы с ребром j<i, глубина D=0,1,2; минимизируем сумму длин payload (заголовок фиксирован). Точный минимум только для этого конечного набора дельт. Варианты: D0,D1,D2; 7z LZMA2 -mx=5 -mmt=1 -ms=on/off -mtc=off -mta=off -mtm=off; все версии в порядке v1,v2,v3. Проверяем каждый кандидат дельты и все извлечения из всех контейнеров. Для прототипа считаем фактические байты чтения таблицы и payload при извлечении каждого файла с холодным логическим кешем; для 7z измеряем время отдельного процесса и полный размер, но не приписываем фактическое число прочитанных байтов без трассировки. Один прогон, CPU/wall диагностические, память не измеряется. Сравнение скорости Python/7z не является доказательством преимущества алгоритма.

## Gate
Размер D1 (заранее выбранная основная конфигурация): >=10% экономии по сумме четырёх реальных семейств относительно solid 7z и победа минимум на двух. D2, D0 и синтетика — диагностические. Любая ошибка восстановления останавливает эксперимент. При проигрыше отклонить данный способ в качестве универсального слоя; независимо от результата не интегрировать без более разнообразного независимого корпуса и сильных дельта-контролей. Выигрыш по размеру не заменяет проверку стоимости доступа, CPU и памяти.
