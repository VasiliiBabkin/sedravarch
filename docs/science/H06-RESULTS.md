# H06 — результаты моделирования числовых последовательностей

**Решение:** H06a и H06b не прошли общий заранее заданный gate. Известные фиксированные предикторы дают значимый локальный выигрыш на двух реальных семействах; адаптивную схему выбора по маргинальным энтропиям отклонить. H06c: локальный порог не достигнут на реальных массивах, достигнут только на синтетике. Не интегрировать.

## H06a: предикторы
На ECG все четыре окна выиграли 30.57–32.37%; победил delta2 + byte shuffle (три XZ5, один Z15). На M4 все 12 рядов выиграли 32.89–41.16% через delta2 + bitshuffle + Z15. Все семь ETTh1: лучший вариант identity + XZ5, 0% выигрыша. Порог >=10% на каждой панели не пройден. Два семейства являются основанием для дальнейшего узкого исследования, но эти известные операции не демонстрируют преимущество над специализированными готовыми кодерами.

## H06b: маргинальная энтропия как суррогат
Все три реальные панели проиграли фиксированному oracle. На ECG 252/256 блоков выбрали delta2, 4 delta1; обязательная bitshuffle и теги ухудшили размер относительно лучшего byte shuffle. На M4 все 24 блока выбрали XOR, хотя лучшие реальные потоки всех 12 массивов использовали delta2 + bitshuffle + Z15. Это наблюдаемый контрпример к использованию суммы энтропий отдельных битовых полос в качестве достаточного критерия выбора представления. На ETTh1 423/448 блоков выбрали identity, 24 XOR, 1 delta1; обязательная глобальная bitshuffle и переключения дали почти трёхкратный размер относительно прямого XZ. Причины раздельно не измерялись: смена модели, перестановка, накладные расходы и другой backend смешаны. Не приписывать весь проигрыш только предиктору. Не оптимизировать текущую архитектуру выбора.

## H06c: точное целочисленное представление
12 M4 из 12 допустили scale=0, т.е. эти выбранные вещественные массивы фактически представляют целые числа. Сумма decimal-best 8230 B vs fixed 8317 B (1.0461% экономии), наибольшая локальная экономия 5.18% (H12). На всех семи ETTh1 подходящего общего scale=0..6 нет; это не доказательство невозможности иных точных представлений или схем с исключениями. Synthetic decimal-f64: scale=2, 36369→31479 B (13.45%). Synthetic sin-f64 не прошёл тест точности. В целом 13/21 float64 массивов допускают один из проверенных масштабов. Локальный порог >=10% достигнут только на synthetic; нет основания считать гипотезу конкурентоспособной. Точное целочисленное представление десятичных float известно, в частности в ALP (Afroozeh, Kuffó, Boncz, https://ir.cwi.nl/pub/33334, https://github.com/cwida/ALP). Сравнение с ALP не выполнено.

## Ограничения
Новые источники — публичные screening-панели, не слепой holdout; окна одного ECG, колонки одного ETTh1 и серии одной категории M4 не независимые выборки. Не проверены другие форматы и длинные многомерные массивы. Перестановки реализованы на всей матрице, не оптимизированный блочный Bitshuffle. Контрольное меню использует известные операции, но не полноценные Gorilla, FLAC, ALP или другие специализированные кодеры; сравнение с ними необходимо до вывода о превосходстве. Один прогон, RSS не измеряется; CPU фиксированного предиктора включает вычисление всех четырёх residuals, поэтому не пригоден для честного сравнения нативной скорости. Декодер только для доверенных потоков; NaN/Inf/-0 не исследованы отдельным корпусом, нет fuzzing. Временные скачанные данные очищены, источник воспроизводим по хешам. Новизна не установлена.
