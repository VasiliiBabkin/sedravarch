# H08 — архивы групп версий: дедупликация и выборочный доступ
Дата 24.11.2026. Протокол до измерений.
## Гипотеза
H08a: индексированный архив с content-defined chunking (CDC), дедупликацией и независимо сжимаемыми страницами обеспечивает практически полезный компромисс между хранением и чтением. Это не новый CDC: см. Xia et al., FastCDC, USENIX ATC 2016, https://www.usenix.org/conference/atc16/technical-sessions/presentation/xia; Git pack format https://git-scm.com/docs/pack-format и https://git-scm.com/docs/git-pack-objects. Проверяем конкретную композицию и стоимость доступа.
## Данные
Три реальные семьи по 12 версий, более крупные чем H03:
- madler/zlib, inflate.c, tags v1.2.3, v1.2.4, v1.2.5, v1.2.6, v1.2.7, v1.2.8, v1.2.9, v1.2.11, v1.2.12, v1.2.13, v1.3, v1.3.1.
- pnggroup/libpng, pngwrite.c, tags v1.6.30–v1.6.41.
- git/git, read-cache.c, tags v2.30.0–v2.41.0.
Порядок указанных версий, имена v01.bin–v12.bin. HTTPS raw.githubusercontent.com, до 2 MiB на файл, SHA-256 каждого. Если версия отсутствует, пропуск всей семьи; при неполной панели gate не проверен. Все три исходники отличны от H03; открытая однородная панель, не слепой holdout. Синтетика: 12 версий 128 КиБ random seed 20261124, в каждом следующем файле 64 случайных замен и вставка 31 случайного байта в случайном месте, предыдущий файл основа. Дубликаты не удалять из списка имён.
## Представления
Fixed: чанки 4096 B. CDC: Gear 64-bit h=((h<<1)+table[byte]) mod 2^64, таблица Python Random(20261124).getrandbits(64) 256 раз. Сброс на границе, min1024/max8192, cut если h&4095==0 после min. Не FastCDC. Точная дедупликация через SHA-256 и сравнение байтов. Первое появление определяет порядок уникальных чанков. Pack pages: складывать целые уникальные чанки по порядку в страницы не более 32768 B; каждая отдельный XZ5 CRC64. Варианты fixed-page32, CDC-page32 (основной), CDC-single (каждый чанк отдельная страница).
Контейнер: magic 4B, u32 длина сжатого индекса; индекс zlib9, содержит u32 числа страниц/чанков/файлов, таблицу u32 encoded length страниц, таблицу (page id, offset, length) u32 чанков, для каждого файла u16 name length+имя, u32 original length, CRC32, u32 count и u32 refs. Далее payload. Полный размер, все имена и CRC учтены. Декодер читает индекс и только нужные страницы, кеш страниц пуст в каждом запросе; измерить сумму байтов, фактически переданных read() приложению (не физический I/O), и объём декодированных страниц. Сверять весь файл.
Контроли: 7z LZMA2 preset5, mmt=1, solid on/off, timestamps off; Git pack blobs, --window=32 --depth=2 --threads=1 --compression=6 --no-reuse-delta --no-reuse-object --delta-base-offset; учитывать .pack + .idx + бинарное отображение имён в 20B SHA1 object ID (u32 count, u16 length + name + id). Отдельное пустое bare repo с только pack/idx для восстановления. Git config/runtime не включать в размер, аналогично программам кодеров. Проверять map и каждый восстановленный объект. Не считать raw loose objects частью архива. Внешние кодеры используют разные форматы.
## Измерение и gate
Один encode каждого профиля, CPU где возможно и wall диагностически. 3 повторения выборочного извлечения каждого файла в отдельном процессе для всех профилей, порядок профилей детерминированно перемешан по имени и повтору. Warm OS cache; никакого сброса системных кешей, только пустой application cache. Все выходы сверить побайтово. Сумма медиан wall по 12 запросам, не чистая скорость кодека: включает запуск Python/Git/7z, проверку CRC внутри формата, но не внешнее сравнение. Логическое чтение доступно только собственным профилям, не сравнивать его с неизмеренным I/O Git/7z. RSS не измерять.
H08a screening: CDC-page32 должен быть не более 110% per-family min(7z solid,Git pack+idx+map) по размеру на КАЖДОЙ реальной семье, при сумме логических read bytes по 12 запросам <=35% от 12*полный размер своего архива и амплификации декодированных страниц <=2 относительно запрошенных байтов. Это критерий собственной адресуемости, НЕ доказательство более быстрого доступа чем Git/7z.
H08b практическая диагностическая проверка: при <=110% размера сильнейшего контроля CDC-page32 должен сократить wall извлечения минимум на 30% относительно solid 7z И Git pack (каждый отдельно) на всех реальных семьях. При проигрыше не интегрировать. Оба gate предварительные, без независимых нетекстовых семейств и памяти никакого production GO. Не изменять пороги после измерений.
