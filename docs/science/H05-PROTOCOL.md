# H05 — управление вычислительным бюджетом
Протокол до запуска, цикл 1.

## Гипотеза
H05a: дешёвый предварительный отбор позволяет приблизиться к минимуму полного перебора сильных кодеров при меньшем времени. H05b: политика даёт практически полезный выигрыш относительно фиксированного XZ5. Это исследование алгоритма выбора, не новый алгоритм сжатия. Rice, The Algorithm Selection Problem (1976), https://doi.org/10.1016/S0065-2458(08)60520-3; Dean & Boddy, An Analysis of Time-Dependent Planning (1988), https://mlanthology.org/aaai/1988/dean1988aaai-analysis/; Farruggia et al., Bicriteria Data Compression (2014), https://doi.org/10.1137/1.9781611973402. Последняя работа оптимизирует размер и время декодирования LZ77, а здесь оценивается время кодирования и выбора.

## Данные
7 synthetic и 11 Canterbury: первые min(n,131072) байт, 12 Silesia: центральные 131072 байта (floor((n−131072)/2)). 30 образцов. Публичные панели не holdout; synthetic — диагностическая. Проверить SHA-256 целых файлов из манифеста, записать хеши окон. Никакой настройки по результатам.

## Кандидаты
Raw, Zstandard levels 3 и 15 (libzstd, однопоточный ZSTD_compress), Python lzma XZ preset 5 CRC64. Единая рамка 13B: magic H05A, tag u8, исходный размер u32, CRC32 u32. Все профили включают raw fallback, при равенстве выбирается меньший tag. Политики: Z3, Z15, XZ5 (каждая один кодер плюс raw); Exhaustive (все три плюс raw); Adaptive.
Adaptive: сначала полная Z3 с raw fallback. Если n<=12288, вычислить остальные полные кандидаты, без отдельных проб. Иначе взять три окна по 4096 байт (начало, floor((n−4096)/2), конец), соединить без разделителей; сжать эту пробу каждым из трёх кодеров. Выбрать меньший из Z15 и XZ5 по размеру пробы (при равенстве Z15). Если выигрыш относительно min(raw,z3) на пробе не менее max(32 B, ceil(0.01*min(raw,z3))), запустить выбранный дорогой кодер на полном блоке; иначе остановиться. Всегда вернуть самое короткое из реально полученных полных представлений. Сэмпл может искажать расстояния и не отражать локальную неоднородность; это фиксированная эвристика, не оценка математического ожидания с доказанной калибровкой.

## Измерение
3 повторения каждого профиля на каждом образце, детерминированное перемешивание порядка по SHA-256 и номеру повтора. Реальный encode каждого профиля, CPU и wall включают создание пробы, её сжатие, выбор и формирование рамки/CRC. Не эмулируем затраты по трассе. Декодирование измеряем отдельно, каждый поток сверяем с исходником. Суммируем медианы CPU и размеры по образцам (проверить детерминированность), на каждой панели. Один CPU affinity, nice +10, без внешних процессов на отдельный поток. Отсутствует измерение RSS; не заявляем системное превосходство. Декодер только для собственных потоков. Входные данные не исполняются.

## Gate
H05a: Adaptive не более чем на 1% больше Exhaustive и CPU не более 70% Exhaustive на каждой публичной панели.
H05b: Adaptive не более чем на 1% больше XZ5 и CPU не более 70% XZ5 на каждой публичной панели. Дополнительно отмечаем доминирование фиксированных профилей (не хуже по размеру и CPU, строго лучше по одному). Если H05a проходит, а H05b нет, это лишь экономия поиска, не преимущество над сильным фиксированным кодером. В любом случае нет интеграции до независимого holdout и более широких контрольных профилей. Ошибка восстановления останавливает опыт. Не менять gate задним числом.
