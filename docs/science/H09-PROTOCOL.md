# H09 — точное структурное представление DEFLATE
Протокол до измерений. RFC 1951 https://www.rfc-editor.org/rfc/rfc1951.html; Microsoft preflate-rs https://github.com/microsoft/preflate-rs предсказывает токены и кодирует поправки. Здесь исследуется более простая, независимая от версии zlib модель, не заявка на новизну и не реализация preflate.
## Данные
Повторная диагностическая панель H07b.2: все 15 файлов из закреплённых URL исходного H07B2-20261124.jsonl. Сверить SHA-256; прежние реально измеренные и проверенные XZ5/Zstd15/7z/Precomp+XZ5 размеры использовать только при совпадении хеша. Это НЕ новый holdout. Детектор H07b.2 (проверенный исходник SHA-256 cb984396ad8b5a118260f5e13d50e34d1eb8dab099a8b9c254cb2fc3fcdc0fc6), дополнительно ограничить каждый поток 128 KiB compressed/256 KiB plain и первые 1 MiB plain в сумме на файл, порядок смещений. Пропуск при лимите; не считать недетектированные потоки. Synthetic: первые 32768 B alice29.txt, synthetic random и repeated (если имена из manifest; выбрать по путям random.bin/repeat.bin) и сформированный текст, raw DEFLATE level 0, level 6 default, level 6 fixed, level 6 с Z_SYNC_FLUSH на половине. Контроль восстановления stored/fixed/dynamic, нестандартных границ; synthetic только проверка корректности.
## Представление
Разобрать RFC1951: точные биты заголовков блоков (включая dynamic Huffman lengths, RLE и stored alignment/LEN/NLEN), затем последовательность literal runs и match records (u32 count literals before match, length symbol offset u8, extra length u8, distance symbol u8, extra distance u16), сохранять код длины отдельно для неоднозначных представлений. End-of-block выводится из таблицы; final padding сохраняется. На блоке хранить число выходных байтов и число совпадений. Две модели: L — отдельные literal bytes; P — весь распакованный поток, включая данные совпадений. При восстановлении P литералы берутся из plaintext, match lengths/distance задают исходные команды. Заголовки, matches и data сериализуются в отдельные полосы, длины u32, затем внешний XZ5. Контейнеры zlib/PNG: сохранить исходные заголовок и Adler, точные длины IDAT; сверить полный участок; ZIP raw DEFLATE. Не требуется повторное сжатие zlib. Оба структурных представления декодировать в исходный битовый поток, сверить с оригиналом и проверенным plaintext. Измерить размер каждой полосы при отдельном XZ5 (диагностика, не аддитивная стоимость общего потока). 
Для полного файла: raw record tag0/u32 length/original bytes или structural record tag1/u32 length/metadata+structural stream. Выбирать преобразование только если XZ5 над полной локальной записью строго меньше XZ5 над raw. Внешняя рамка magic+u32 original length+CRC32 и XZ5 над всеми записями. Для L и P отдельно. Оба полных файла восстановить и сверить. Сумма per-file min(L,P,old ordinary control) — диагностический oracle; основной P с локальным отбором. 
## Gate
P должен быть <=95% суммы per-file min прежних сильных контролей (включая Precomp+XZ5) и выиграть >=8 из 15 файлов при полных данных. L diagnostic. Не менять критерий. Если не проходит, не реализовывать промышленный кодер по этой схеме. Один run, один CPU, nice +10; только размеры, wall диагностически, RSS не измеряется. Ограниченные доверенные потоки; нет fuzzing, современный preflate не проверен. Не заявлять превосходство над preflate при успехе.
