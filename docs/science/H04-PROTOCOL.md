# H04 — адаптивные контекстные вероятности
Дата: 24.11.2026, протокол до запуска.

## Гипотеза
H04a: ограниченные битовые контекстные модели с адаптивным смешиванием дают ≥5% экономии полного потока на каждой публичной панели относительно сильнейшего из двух контролей (минимум размера XZ preset 5 и 7z PPMd preset 5 для каждого образца). H04b: смесь экономит ≥2% против лучшего единственного фиксированного порядка, выбранного по суммарному размеру каждой панели. Это screening, не новая реализация PPM или CTW. Источники: Cleary & Witten, 1984, https://doi.org/10.1109/TCOM.1984.1096090; Witten, Neal & Cleary, 1987, https://doi.org/10.1145/214762.214771; Willems, Shtarkov & Tjalkens, 1995, https://www.itsoc.org/publications/papers/the-context-tree-weighting-method-basic-properties.

## Модели
Для очередного бита (MSB first) контекст: префикс текущего байта (начальный узел 1, затем 2*prefix+bit) и последние k байтов, k=0,1,2,4; недостающие байты нулевые. 65536 ячеек на порядок, детерминированное хеширование ((history & mask)*257+prefix)*2654435761 modulo 2^32, индекс старшие 16 бит. Коллизии намеренны. Счётчики n0,n1 начинаются с нуля. KT-подобная оценка p(1)=(2n1+1)/(2(n0+n1)+2), округление вниз в шкале Q=32768, ограничение 1..32767. После бита увеличить соответствующий счётчик, если сумма >=4096 — целочисленно поделить оба пополам. Модель обучается только на декодированном префиксе, таблицы не сериализуются.

Пять кандидатов: k=0,1,2,4 и смесь этих четырёх. Смесь: начальные веса 16384, целочисленное среднее p=sum(w*p_i)//sum(w), ограничение 1..Q−1; после наблюдения likelihood l_i=p_i для 1, иначе Q−p_i, веса обновляются w_i=64+floor((65536−256)*w_i*l_i/sum(w_j*l_j)). Это фиксированная доля веса с забыванием, не точный Bayesian mixture или CTW; не заявляем их теоретические гарантии. Для каждого бита измеряем -log2 вероятности фактически наблюдённого бита (после квантизации).

Действительное 32-битовое двоичное арифметическое кодирование E1/E2/E3, завершение и нулевое дополнение последнего байта. Контейнер magic 4B, model id 1B, исходный размер u32, CRC32 u32, payload; 13 байт заголовка. Все кандидаты декодируются и проверяются побайтово. Декодер читает нули за концом битового потока, исследовательский, не для недоверенных данных. Контроли: Python lzma FORMAT_XZ preset 5 CRC64; 7z PPMd -mx=5 -mmt=1 -mtc=off -mta=off -mtm=off с именем input.bin, проверка извлечения. 7z включает имя, XZ и опыт — нет; накладные расходы явно отмечаются. Сохраняем фактические размеры, логарифмические потери, CPU/время, хеши, параметры. Oracle (минимум 5 моделей) диагностический; основная модель смесь, без подгонки. Скорость Python против нативных контролей не является доказательством алгоритмической скорости.

## Данные и критерии
7 synthetic, 11 Canterbury: первые min(n,8192) байта; 12 Silesia: центральные 8192 байта (floor((n−8192)/2)). Итого 30 образцов, нет обучения на внешних данных; публичные панели не holdout. Суммируем по панелям. H04a проходит только если смесь экономит >=5% на каждой из двух публичных панелей по сравнению с суммой per-sample min(XZ,PPMd). H04b проходит только если смесь экономит >=2% относительно минимума суммарных размеров четырёх фиксированных порядков на каждой публичной панели. Локальные улучшения >=10% — повод для отдельной гипотезы, не для общего вывода. Ошибка восстановления останавливает опыт. При непрохождении gate не интегрируем этот вариант; не опровергаем PPM/CTW или другие контекстные модели. Один запуск, короткие окна, без измерения RAM, без независимого holdout.
