# H02 — бинарные грамматики и стоимость их сериализации
Дата: 2026-11-24. Протокол до запуска.

## Гипотеза и научная база
H02a: жадное построение бинарной ациклической грамматики с повторным использованием правил даёт практически значимое преимущество по полному размеру над прямым XZ/LZMA2 preset 5. Это проверка конкретного ограниченного подхода, не изобретение грамматического сжатия. Re-Pair (Larsson, Moffat, 1999; https://dblp.org/rec/conf/dcc/LarssonM99.html) заменяет частые пары; SEQUITUR (Nevill-Manning, Witten, 1997; https://doi.org/10.1093/comjnl/40.2_and_3/103) выводит иерархические правила. Минимальная грамматика в классической постановке NP-трудна (Charikar et al., 2005; https://doi.org/10.1109/TIT.2005.850116). Минимум числа символов не равен минимуму байтов сериализации.

## Метод
Алфавит терминалов 0..255; правило 256+i -> (a,b), где a,b < 256+i. Начальная строка заменяется последовательностью терминалов и ссылок. Если k непересекающихся вхождений пары заменить новым символом, число символов в строке сокращается на k, число символов в правых частях правил растёт на 2; чистое сокращение k−2 при одинаковой цене символа. Учитываем перекрытие (например, AAA содержит два AA, но только одно непересекающееся вхождение). Частоты всех соседних пар пересчитываются каждый раунд; выбирается самая частая, при равенстве — меньшая пара в лексикографическом порядке. Для выбранной пары заменяются непересекающиеся вхождения слева направо. При менее 3 заменах прекращаем поиск, даже если другая пара могла быть полезнее. Это упрощённый Re-Pair-подобный прототип, не оптимизированный Re-Pair.

Проверяем состояния после максимум 16, 64, 256 правил (если остановка раньше, используем последнее состояние). Для каждого два формата: все символы u16 LE подряд и их байтовые полосы (сначала младшие байты всех символов, затем старшие). Внутренний заголовок: u32 длина исходника, u32 число правил; затем 2r символов правил и остаточная строка. Весь внутренний поток сжимается Python lzma FORMAT_XZ preset 5 CRC64. Снаружи один байт тега: 0 = прямой XZ, 1 = interleaved, 2 = split. Правила и заголовки включены в размер. Базовый контроль — обычный XZ без тега. Шесть грамматических кандидатов плюс direct+tag; oracle = минимальная длина, включая селектор. Каждый кандидат восстанавливается из сериализованного потока, сверяется побайтово. Суммарное число символов, CPU построения и кодирования сохраняются. Время не является критерием допуска на этом этапе.

## Данные и критерий
7 synthetic (первые min(n,32768) байт), 11 Canterbury (первые min(n,32768) байт), 12 Silesia (центральные 32768 байт, смещение floor((n-32768)/2)). Итого 30 образцов, публичные панели не являются независимым holdout. Нет обучения. Хешируем исходные файлы и окна. Каждый образец сжимается самостоятельно. Размеры суммируются отдельно по панелям. Для продолжения универсальной ветви именно этого прототипа oracle должен сэкономить >=5% на каждой публичной панели относительно прямого XZ; иначе не оптимизируем этот вариант. Локальные выигрыши >=10% — основание только для новой гипотезы. Ошибка восстановления останавливает опыт. Порог не изменяется после запуска. Нельзя делать вывод обо всех грамматических кодерах, более глубоких грамматиках, другом энтропийном кодировании или полных файлах. Никакой претензии на научную новизну.
